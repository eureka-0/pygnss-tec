# T029: Migrate Python docstrings to NumPy style

[Task index](../../ROADMAP.md).

## Objective

Use NumPy-style package docstrings and make TECConfig defaults, units,
constraints and output behavior discoverable through class and field hover.

## Context and Scope

Delivered with T027/T028. Covers `gnss_tec/` reader/TEC APIs, mapping/bias
utilities, configuration class/field/property/method documentation, README
examples and the convention in AGENTS.md. Simple helpers remain concise.

## Implementation Plan

1. Inventory structured package docstrings and convert existing Google-style
   sections to Parameters, Returns/Yields, Raises and applicable attributes.
2. Document all TECConfig parameters and effective code-priority defaults,
   units, validation, frozen/keyword-only behavior and diagnostic modes.
   Keep field-level docstrings for instance hover and document public methods
   and properties without runtime wrappers or new dependencies.
3. Preserve scientific qualifications, follow the
   [numpydoc style guide](https://numpydoc.readthedocs.io/en/latest/format.html),
   execute affected examples and inspect actual language-service hover.

## Acceptance Criteria

- [x] Structured package docstrings use NumPy-style sections; no Google-style
  section headings remain, and concise helpers have no empty sections.
- [x] Signatures, defaults, units, supported inputs and exceptions agree with
  the delivered T027/T028 contracts and current scientific behavior.
- [x] TECConfig class/constructor, instance fields and public properties/methods
  expose complete descriptions; AGENTS.md records the convention.
- [x] Python 3.12 compatibility, lint/format checks and README examples pass.
- [x] Actual ty hover was inspected and its constructor-keyword limitation is
  explicitly recorded rather than claimed as verified parameter prose.

## Validation

Use package heading inspection, Ruff/ty and executable README examples.
Inspect the actual LSP hover responses for a class reference, constructor,
constructor keyword, instance field and public property. Evidence and tool
limits are recorded in [validation](../agents/next-implementation-validation.md).

## Progress & Handoff

**Implemented:** converted reader/TEC/bias/mapping documentation and completed
TECConfig class, fields and public methods/properties. No runtime wrappers or
documentation dependencies were added.

**Verified:** actual ty class/constructor, instance-field and property hover
include the descriptions. The constructor keyword hover provides type/default
only; ty does not surface its parameter prose there. The complete parameter
contract is available on constructor and instance-field hover.

**Next:** retain these documentation conventions when implementing the open
correctness tasks; no remaining implementation in this delivery group.
