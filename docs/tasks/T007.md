# T007: Make SNR filtering and leveling robust

[Task index](../../ROADMAP.md).

## Objective

Separate missing-SNR policy from low-SNR rejection; use robust code-phase offsets and report support/residual statistics.

## Context

R02 fixes usable-candidate ranking under the existing SNR policy. This task separately changes SNR/leveling robustness; the two scopes should not be conflated.

## Scope

`gnss_tec/calculation/tec.py`, `gnss_tec/configuration.py`.

## Implementation Plan

1. Inventory the current missing/low-SNR policy and code-phase offset estimator; construct paired controls with/without unrelated satellites and controlled code outliers.
2. Propose an explicit missing-SNR policy separate from low-SNR rejection and a robust offset estimator with support/residual diagnostics; quantify possible retention and leveling changes.
3. Review scientific/default-policy changes before implementing the chosen policy and estimator; preserve raw observations and physical arc boundaries.
4. Verify QC independence from unrelated satellites and outlier-resistant leveling on independent constant-TEC/noise controls; report retention/residual changes.

## Acceptance Criteria

- [ ] unrelated satellites cannot alter existing QC decisions; code outliers do not shift a whole valid arc unchecked.
- [ ] Missing-SNR treatment, minimum support and residual meanings are documented; diagnostics explain estimator rejection rather than hiding it.

## Validation

Compare QC masks and retained identities before/after adding unrelated satellites. Use known constant/ramping TEC and injected code outliers; check that robust offsets retain genuine changes and do not shift a whole valid arc unchecked.

## Progress & Handoff

**Next:** Define the SNR-policy and leveling reference cases. The robust estimator and any default-policy change are unapproved proposals.
