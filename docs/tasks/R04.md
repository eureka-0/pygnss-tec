# R04: Distinguish metadata events from ambiguity resets

[Task index](../../ROADMAP.md).

## Objective

Classify timestamped event contents before changing ambiguity state; preserve retained general events without forcing a reset.

## Context

Metadata-only events and ambiguity resets require different handling. R03 omits blank-epoch events; this task classifies retained timestamped events. Its timed-event cases can be developed independently.

## Scope

`gnss_tec/calculation/observation_geometry.py`, `gnss_tec/signals/arcs.py`, `tests/test_cycle_slip.py`.

## Implementation Plan

1. Reproduce COMMENT-only flag-4 and non-reset flag-5 cases with continuous phase and the constant-30-TECU/code-noise fixture; inspect the preparation-to-QC state path.
2. Specify a classification for retained timestamped events: flag 1 indicates a power interruption; flags 2/3 describe antenna/site transitions; flag 4 requires inspection of header contents; flag 5 requires its external-event meaning. COMMENT-only flag 4 and non-reset flag 5 must preserve continuity. Keep R01's flag-6 payloads out of observation values. Unknown retained contents need an explicit reviewed policy.
3. Apply the reviewed classification below; replace blanket event-state increments with reset evidence and retain timestamped event metadata. Omitted blank-epoch events must not be assigned to a nearby observation or reintroduced as state changes.
4. Verify non-reset continuity, actual reset splits, pair switches and cross-midnight behavior, and document the classification limits.

### Reviewed classification

The user approved this classification on 2026-10-15 before dependent implementation. The [RINEX 3.05 specification, Table A3](https://files.igs.org/pub/data/format/rinex305.pdf) defines event meanings; conservative treatment of ambiguous contents is library policy.

| Retained event | Reviewed ambiguity handling |
|---|---|
| Flag 1: power failure | Split at the event epoch. |
| Flags 2/3: antenna movement/new occupation | Split conservatively at the event epoch. |
| Flag 4 with only COMMENT records, or no records | Preserve continuity. |
| Flag 4 with any other header record, malformed record, or unknown contents | Split conservatively; applying changed header values to geometry/observations remains outside this fix. |
| Flag 5: external event | Preserve continuity; the format does not define a receiver/phase reset for this flag. Do not infer resets from free-text keywords. Independent LLI, power, receiver identity and explicit receiver-state evidence still split. |
| Flag 6: cycle-slip records | Keep payloads in event metadata and split conservatively at the event epoch; never substitute slip counts for observations. Per-satellite slip interpretation is outside this fix. |

Use one cumulative state per distinct reset epoch, sorted and deduplicated. COMMENT-only and flag-5 events remain in `epoch_events`. An explicit input `receiver_state` remains authoritative. Check both header-based events and row-level `epoch_flag` inputs, and preserve the existing Python/native basic-arc equivalence.

## Acceptance Criteria

- [x] COMMENT-only flag 4 and non-reset flag 5 do not split continuous phase; the constant-30-TECU/code-noise fixture stays at 30 rather than acquiring a 29/31-TECU leveling step, while actual resets still split arcs.
- [x] Actual receiver/ambiguity resets still produce distinct physical arcs; timestamped event retention is not removed to avoid splitting.

## Validation

Use independent physical expectations in cycle-slip and multi-day cases. Compare arc/level identifiers and TEC values: metadata-only events retain continuous phase and 30 TECU; true resets still split. Do not accept a merely lower number of arcs as proof of correctness.
