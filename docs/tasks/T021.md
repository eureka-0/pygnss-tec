# T021: Add Rust failure-path tests and parser fuzzing

[Task index](../../ROADMAP.md).

## Objective

Exercise truncated/compressed files, conflicting headers, bad epochs and merge errors; assess panic-abort behavior.

## Context

Malformed native input must not silently corrupt data or terminate normal processing. Parser failure paths and panic-abort behavior need explicit, isolated validation.

## Scope

`src/`, Rust test/fuzz targets, `Cargo.toml`, CI.

## Implementation Plan

1. Inventory Rust error boundaries, compressed/truncated input handling, merge errors and build panic settings.
2. Specify a small adversarial corpus covering truncated/compressed files, conflicting headers, bad epochs and merge failures; propose fuzz boundaries and execution resource limits.
3. Review any native error/public exception contract change; add failure-path tests and narrowly scoped fuzz targets/CI integration.
4. Run malformed-input checks in isolated processes where termination is possible, verify actionable failures, and retain/reduce reproducible fuzz findings.

## Acceptance Criteria

- [ ] malformed input cannot silently corrupt data or unexpectedly terminate normal processing.
- [ ] Native error paths preserve valid data and return documented errors; any panic/abort behavior is assessed explicitly rather than hidden by a green valid-input suite.

## Validation

Run current Rust checks plus adversarial corpus/fuzz targets with recorded seeds/configuration and isolated termination checks. Verify no partial corrupt output and correct exceptions/context at the Python boundary.

## Progress & Handoff

**Next:** Inventory native error/panic paths and define the malformed-input corpus. Fuzz target/tooling choices are still proposals.
