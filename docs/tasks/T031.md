# T031: Apply timestamped RINEX header updates

[Task index](../../ROADMAP.md).

## Objective

Apply supported timestamped header changes to the observations and geometry they govern. Preserve raw event metadata, use the header state effective at each record and reject unsupported scientifically significant updates explicitly instead of silently using stale values.

## Context

R03/R04 deliberately separate event retention/reset classification from applying new header contents. Current receiver history represents file-level metadata; a retained flag-4 update can trigger a conservative reset without applying its new receiver coordinates or parser settings. Upstream parsing may already handle some fields: audit each field before adding transformations to avoid double application.

## Scope

`src/quality.rs`, `src/rinex_io.rs`, observation ingestion, `gnss_tec/io/rinex.py`, header metadata/serialization and `gnss_tec/calculation/observation_geometry.py`. Cover supported RINEX 2/3 and compression/multi-file paths. T011 continues to own the signal registry and legacy bias/tracking bridges; this task owns effective header state.

## Implementation Plan

1. Build a field-by-field support matrix against the RINEX specification, upstream parser and Hatanaka decoder. Separate harmless descriptive records from parser-critical observation lists/scales/phase conventions and geometry/receiver/antenna fields. Record which layer currently applies each field, which needs work and which must be rejected or explicitly limited.
2. Review a canonical ordered header-state timeline and effective-record semantics. Retain epoch and source order for multiple updates at one time; define before/after behavior for same-epoch observations, conflicts/overlaps across files and metadata serialization. Do not add provenance columns to public observation tables merely to carry internal state.
3. Apply supported parser-critical changes during decoding/framing, including RINEX 2 observation counts/continuations and version-specific wavelength/scale conventions. Applying only final Python column labels is insufficient when record layout changes. Verify decoder behavior before updating or reinitializing state; never apply an upstream conversion twice.
4. Apply supported receiver/site/antenna changes to subsequent geometry and receiver identity/state using the reviewed effective epochs. Preserve explicit caller-supplied coordinate/state precedence. Keep data parsing, scientific value changes and ambiguity-reset evidence distinct; COMMENT-only records remain harmless.
5. For scientifically significant updates outside the reviewed support matrix, provide an actionable unsupported-input failure or reviewed explicit limitation before returning misleading values. Preserve R03's policy: blank-epoch events remain consumed/omitted without invented update times or state transitions.
6. Verify supported updates and publish the field/version support table, effective-time behavior and remaining restrictions. Coordinate the effective observation-code/phase context with T032 and the repair eligibility checks in T030.

## Acceptance Criteria

- [ ] Every supported changed field is applied exactly once to the intended records; earlier records retain their original interpretation and geometry.
- [ ] Changed coordinates/receiver identity and parser-critical layouts are covered with explicit before/after expectations, including multiple same-time updates and unchanged COMMENT cases.
- [ ] Compressed, RINEX 2/3, multi-file and metadata round-trip paths preserve the same state timeline and avoid parser desynchronization or stale geometry.
- [ ] Unsupported/malformed significant updates have explicit behavior; omitted blank-epoch events are never applied at fabricated times. Explicit user inputs retain reviewed precedence.
- [ ] The active field/order/wavelength context is available to T032/T030 without silently expanding signal support or reinterpreting raw data.

## Validation

Use small independently constructed files changing receiver ECEF, identity and supported observation/scale/phase fields at known record boundaries. Check exact observation identities/units and independent geometry before/after each update. Exercise conflicts, same-time records, comments, malformed/unsupported labels, compression, multi-file overlap and metadata serialization. Keep the support matrix and scientific evidence outside this task record.

## Progress & Handoff

**Next:** audit the parser/decoder and build the support matrix, then review timeline and failure policies before implementation. No claim is made that all possible RINEX header changes are currently supported.
