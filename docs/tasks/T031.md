# T031: Apply timestamped RINEX header updates

[Task index](../../ROADMAP.md).

## Objective

Apply supported timestamped header changes to the observations and geometry they govern.
Preserve raw event metadata, use the header state effective at each record and reject unsupported scientifically significant updates explicitly instead of silently using stale values.

## Context

R03/R04 deliberately separate event retention/reset classification from applying new header contents.
At commit `1b9130f`, `ObservationReader` initializes observation order, RINEX 2 framing counts and the decoder from the initial header, then withholds special-event blocks from upstream observation parsing.
Python `receiver_history` describes per-file initial coordinates and identity; retained flag-4 contents do not update that timeline.
The file-level `phase_integer_cycles` marker describes declarations rather than an effective per-record interpretation.
Audit upstream handling of initial-header conversions separately to avoid double application.

R05/T005/T030 are archived.
Preserve their delivered temporal-continuity contract and raw observations; carrier-integer identification is outside this task.

## Scope

`src/io/quality.rs`, `src/io/rinex.rs`, `src/io/observations.rs`, `gnss_tec/io/rinex.py`, header metadata/serialization and `gnss_tec/calculation/observation_geometry.py`.
Cover supported RINEX 2/3 and compression/multi-file paths.
T011 continues to own the signal registry and legacy bias/tracking bridges; this task owns effective header state.

## Implementation Plan

1. Build a field-by-field support matrix against the applicable RINEX 2/3 specifications, upstream parser and Hatanaka decoder.
   Separate harmless descriptive records from observation lists, scale/wavelength/phase conventions, time declarations and receiver/site/antenna fields.
   For each field/version, identify framing, decoding, value conversion, geometry and reset effects; record supported application or explicit rejection.
   Start with minimal fixtures that expose the current behavior before proposing changes.
2. Submit the support matrix and canonical ordered header-state model for human review before implementation.
   Resolve same-time source order, before/after observation semantics, multi-file overlaps/conflicts, caller-supplied coordinate/state precedence and unsupported-update behavior.
   Review metadata serialization and legacy Parquet compatibility; the current merged event tuples alone do not preserve all source-order context.
   Do not add public observation columns merely to carry internal provenance.
3. Apply the reviewed parser-critical transitions during framing/decoding, including RINEX 2 counts/continuations and version-specific observation/scale/phase conventions.
   Demonstrate that records spanning an update stay synchronized and each conversion occurs once.
   Confirm whether the decoder can update its state or needs reinitialization; neither behavior is assumed yet.
4. Apply supported receiver/site/antenna changes to subsequent geometry and receiver identity using the same effective timeline.
   Verify independently calculated before/after geometry and reviewed explicit-input precedence.
   Keep interpretation changes and ambiguity-reset evidence distinct; COMMENT-only records remain harmless.
5. Reject malformed or unsupported scientifically significant updates under the reviewed policy before returning misleading observations or geometry.
   Preserve R03's policy: blank-epoch events remain consumed/omitted without invented timestamps or inherited state.
6. Exercise compressed/uncompressed, multi-file and metadata round-trip paths, then publish the supported-field/version table and effective-time rules in the reader documentation.
   Expose the effective observation-order/phase context needed by T032 without changing the completed continuity algorithm or expanding advertised signal support.

## Acceptance Criteria

- [ ] Every supported changed field is applied exactly once to the intended records; earlier records retain their original interpretation and geometry.
- [ ] Changed coordinates/receiver identity and parser-critical layouts are covered with explicit before/after expectations, including multiple same-time updates and unchanged COMMENT cases.
- [ ] Compressed, RINEX 2/3, multi-file and metadata round-trip paths preserve the same state timeline and avoid parser desynchronization or stale geometry.
- [ ] Unsupported/malformed significant updates have explicit behavior; omitted blank-epoch events are never applied at fabricated times.
  Explicit user inputs retain reviewed precedence.
- [ ] The active field/order/wavelength context is available to event interpretation without silently expanding signal support or changing the completed continuity policy.

## Validation

Use small independently constructed files changing receiver ECEF, identity and supported observation/scale/phase fields at known record boundaries.
Check exact observation identities/units and independent geometry before/after each update.
Exercise conflicts, same-time records, comments, malformed/unsupported labels, compression, multi-file overlap and metadata serialization.
Repeat the reader/event regressions in both layouts and LLI modes, plus affected RINEX-to-TEC and basic/detect/repair paths.
Keep the support matrix and scientific evidence outside this task record.
