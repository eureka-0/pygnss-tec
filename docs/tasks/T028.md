# T028: Simplify TEC output and diagnostic columns

[Task index](../../ROADMAP.md).

## Objective

Separate normal TEC results from optional diagnostics, retain satellite geometry by default, and keep internal leveling/weight/bias-interval fields out of every returned table. Rename `TECConfig.retain_intermediate` to `retain_diagnostics` while preserving selected-column requests.

## Context

Before this delivery, the final projection treated azimuth/elevation as intermediates, exposed several QC/calibration fields by default, and returned internal leveling and bias-interval fields with `"all"`. The changes affect public schemas and configuration naming, not scientific calculations. Delivered with [T027](T027.md) and [T029](T029.md); their shared delivery is not a technical prerequisite relationship.

## Scope

`gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/constants.py`, TEC wrappers/configuration callers, output/QC/bias/compatibility tests, `README.md`, affected examples and `CHANGELOG.md`. Inspect the actual repository and existing local changes before implementation.

## Output Contract

`retain_diagnostics` retains the current accepted values: `None` (default), a list/tuple of column names, or `"all"`.

| Column group | Default (`None`) | Selected-column list/tuple | `"all"` |
|---|---|---|---|
| `azimuth`, `elevation` | Included | Included | Included |
| `epoch_flag`, `L1_lli`, `L2_lli`, `qc_valid`, `qc_reason`, `calibration_status` | Omitted | Include requested columns | Included |
| `mw` | Omitted | Include when requested | Included |
| `tx_bias_start`, `tx_bias_end`, `rx_bias_start`, `rx_bias_end`, `level_id`, `offset`, `weight` | Omitted | Unavailable | Omitted |
| Other existing result/diagnostic columns | Preserve their current result/optional classification | Preserve supported selection | Preserve unless already private |

Default and selected-column modes return accepted rows. `"all"` also retains rejected diagnostic rows, with null public TEC values and rejection reasons. Column selection must not bypass row filtering, calibration policy or QC. The raw RINEX reader's `epoch_flag` remains available independently of this TEC projection.

## Implementation Plan

1. Inventory final schemas for the DataFrame, RINEX and Parquet entry points, configuration construction/update paths, bias/no-bias cases and empty results. Use the current basic-QC implementation as the reference, rather than an older GF/MW plan.
2. Replace `retain_intermediate` with `retain_diagnostics` in configuration fields, type annotations, validation, all callers, tests and documentation. Preserve `None`, list/tuple and `"all"` semantics; document the intentional API rename without maintaining two independently configurable options.
3. Define one final-output policy for base results, selectable diagnostics and fields that are never public. Keep azimuth/elevation in every mode. Move the six QC/calibration columns into selectable diagnostics and remove the seven internal columns listed above from all returned schemas. Ensure selected-column requests cannot restore forbidden fields; use clear existing-style validation for unsupported names.
4. Apply projection after all uses of QC, calibration, bias intervals and leveling state. Keep `weight`, `offset`, `level_id` and interval boundaries internally wherever required. Preserve calculations, physical `arc_id`, validity masks, null TEC for rejected rows and the existing missing-bias policy.
5. Retain `mw` as an optional diagnostic, including explicit list/tuple selection such as `retain_diagnostics=["mw"]`. It is the Melbourne–Wübbena combination in wide-lane cycles; current basic QC checks its finiteness but does not use it to detect unflagged slips. `weight = sin²(elevation)` remains an internal, dimensionless leveling weight and is no longer returned. Do not enable new detection or alter weighting under this task.
6. Update README parameter descriptions, schema descriptions and exact displayed examples; default output includes geometry and hides diagnostics. Document how to request QC/calibration status, the removed fields and the renamed parameter. Convert affected API/configuration docstrings to NumPy style under T029, including complete TECConfig class/field hover documentation for the final output contract. Avoid describing retained TEC as necessarily absolute or fully calibrated just because status is hidden.
7. Verify the combined T027/T028/T029 behavior: RINEX-to-TEC still explicitly reads LLI; default output omits LLI diagnostics while complete diagnostics exposes them. Compare scientific results and row selection before/after projection, then check examples and the configuration rename together.

## Acceptance Criteria

- [x] `retain_diagnostics` replaces the old configuration name consistently and preserves default, selected-column and complete-diagnostic modes.
- [x] Default output includes azimuth/elevation and omits the six QC/calibration diagnostic columns; explicit selections and `"all"` expose the allowed requested diagnostics.
- [x] All modes omit `tx_bias_start`, `tx_bias_end`, `rx_bias_start`, `rx_bias_end`, `level_id`, `offset` and `weight`; column selection cannot reintroduce them.
- [x] `retain_diagnostics=["mw"]` and `retain_diagnostics=("mw",)` return `mw` on accepted rows without enabling all diagnostics; `"all"` also includes it with its current units and computation.
- [x] Output changes preserve internal weighting, leveling and bias-boundary behavior, scientific values, accepted-row selection and existing diagnostic null/reason semantics.
- [x] DataFrame/RINEX/Parquet wrappers, empty outputs and bias/no-bias cases agree on the projection and configuration contract.
- [x] README examples, parameter/schema descriptions, changelog and NumPy-style docstrings match the implementation; TECConfig hover describes the new parameter and its column/row behavior. T027/T029 are delivered in the same run.
