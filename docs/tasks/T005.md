# T005: Move stateful arc kernels out of Python hot loops

[Task index](../../ROADMAP.md).

## Objective

Keep columnar candidate detection; implement validated linear-time per-arc state machines and minimize NumPy/Polars conversions.

## Context

Use validated linear-time per-arc state machines while retaining columnar candidate detection. Removing every Python loop is not the objective.

## Scope

`src/lib.rs`, `gnss_tec/_core.pyi`, `gnss_tec/tec/tec_calculation.py`.

## Implementation Plan

1. Profile the current long/high-rate arc path; identify stateful per-observation loops and conversion/materialization costs.
2. Specify a linear-time kernel's input/output contract: ordering, raw phase, QC reasons, arc/level boundaries and receiver/event state. Keep candidate detection columnar and minimize crossings between NumPy/Polars/native arrays.
3. Review scientific-state or public native-interface changes before implementing the kernel in isolated steps and updating the stub boundary.
4. Compare physical outputs and adversarial state transitions, then measure matched long/high-rate throughput including conversion costs; reject an optimization that weakens QC.

## Acceptance Criteria

- [ ] physical equivalence and a measured throughput improvement on long/high-rate arcs.
- [ ] Raw phase/QC reasons and physical/bias interval separation survive the native boundary; throughput comparisons include conversion/materialization overhead.

## Validation

Use independent slip/reset/TEC-change controls and existing cycle-slip/multi-day/bias regressions; compare all accepted and diagnostic columns. Profile before/after on identical builds, inputs and thread settings.

## Progress & Handoff

**Next:** Profile the actual hot path and define the state-machine contract. Kernel location and conversion tradeoffs are proposals pending evidence.
