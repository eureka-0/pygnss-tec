# T025: Gate publishing on installed-artifact validation

[Task index](../../ROADMAP.md).

## Objective

Test built wheels in clean environments; verify version/dependencies/py.typed/stubs, locked builds, import and minimal RINEX-to-TEC; separately exercise free-threaded artifacts.

## Context

Release gates must validate the exact artifacts being published, in clean installed environments.

## Scope

`.github/workflows/release.yml`, reusable CI workflow, build configuration.

## Implementation Plan

1. Inspect build/release workflows and artifact names; define how the exact built artifacts reach clean validation environments without rebuilding a different wheel.
2. Specify checks for version/dependency metadata, py.typed/stubs, locked build, import and minimal RINEX-to-TEC on the supported environments; design separate free-threaded artifact exercises.
3. Propose and review the release-gate wiring before changing publishing behavior. Implement build/install/run checks and make publishing depend on successful validation of those artifacts.
4. Exercise the workflow without publication where feasible and record hosted/artifact-specific results; retain failures and unsupported environment limits as open evidence.

## Acceptance Criteria

- [ ] publish depends on successful validation of the artifacts being released.
- [ ] The validation provenance identifies the exact wheel/artifact tested and released; free-threaded validation is separate from ordinary supported-version checks.

## Validation

Use clean installed-wheel consumers, metadata/type-file checks and minimal scientific input/output assertions. Check workflow dependency wiring and actual hosted results; a local checkout test or YAML inspection alone does not close this task.

## Progress & Handoff

**Next:** Inspect artifact provenance and draft gate wiring/clean-environment coverage for review. Installed-artifact and hosted release validation remain outstanding.
