# R03: Skip special events with blank epoch fields

[Task index](../../ROADMAP.md).

## Objective

Read special-event records only when they contain an explicit, complete epoch. Skip events with blank epoch fields and their payloads without retaining them or assigning a surrounding observation's timestamp.

## Context

The supported policy is to omit untimed special events. Their record boundaries still have to be consumed correctly so subsequent timestamped observations and events remain readable.

## Scope

`src/quality.rs`, the native reader in `src/lib.rs`, event metadata in `gnss_tec/io/rinex.py`, and `tests/test_rinex_quality.py`.

## Implementation Plan

1. Inspect the supplementary event scanner and upstream parser behavior for RINEX 2/3. Identify any path that inherits an earlier epoch or exposes an untimed special record as an observation/event.
2. Read flags and counts from their fixed field positions before attempting timestamp conversion. Use flag-specific framing: flags 2–5 count following special records, while flag 6 uses observation-like satellite blocks. Distinguish blank epoch fields from malformed nonblank dates; preserve actionable errors for malformed input.
3. For an untimed special event, consume its complete payload but do not append it to `epoch_events`, observations or receiver/ambiguity state. Keep record consumption separate from appending content to a retained event, so skipped payloads cannot attach to an earlier event.
4. Retain timestamped events with their original flags, times and payloads. Keep ordinary epoch-flag 0/1 observations and R01's separation of flag-6 records intact.
5. Apply the same policy to supported compressed inputs and multi-file reads; document the omission in the reader contract. Preserve event metadata round-trips for retained records.

## Acceptance Criteria

- [ ] Blank-epoch special events and their payloads are absent from observation output and returned event metadata.
- [ ] No timestamp is invented or inherited for a skipped event, and it creates no receiver/ambiguity transition.
- [ ] Timestamped special events retain their original time, flag and payload; later observations are neither skipped nor duplicated.
- [ ] Consecutive untimed events, a skipped event between timed events, zero-length payloads and end-of-file cases preserve parser synchronization.
- [ ] Both table layouts, supported RINEX 2/3 compression paths and multi-file reads follow the same policy; retained metadata survives serialization.

## Validation

Use small fixtures combining timed observations, timed events and blank-epoch events. Include payload lines that resemble epoch records to verify count-based skipping. Check observation values/keys/counts and retained event metadata; keep malformed nonblank dates separate from intentionally omitted blank epochs.
