# R03: Preserve special events with blank epoch fields

[Task index](../../ROADMAP.md).

## Objective

Parse flags/counts by RINEX field positions; retain untimed records and define their association with surrounding observations without inventing timestamps.

## Context

Special-event parsing must preserve legal blank-time flag-4 records. Associating untimed events with observations must not fabricate an epoch.

## Scope

`src/quality.rs`, header metadata, `tests/test_rinex_quality.py`.

## Implementation Plan

1. Reproduce a blank-time flag-4 fixture; inspect field-position parsing, event storage and header/Parquet metadata round-trips in the current repository.
2. Propose a representation for untimed events and a documented association rule based on retained ordering/context. Compare preserving an explicit missing time with associating a surrounding observation; do not silently substitute a timestamp.
3. Obtain review of that event/association contract before changing the metadata model. Parse flags/counts by RINEX positions and retain event contents under the reviewed contract.
4. Verify observation counts/values and both layouts remain unchanged, then document the association and any remaining limits.

## Acceptance Criteria

- [ ] legal blank-time flag-4 records survive reading and metadata round-trip, with unchanged observation values/counts.
- [ ] Untimed event contents and ordering/context survive the supported metadata round-trip; no timestamp is invented.

## Validation

Use minimal RINEX 2/3 timed and blank-time event fixtures, header serialization and existing reader-quality tests. Compare observation keys, values, counts and event contents before/after; test association around file/day boundaries where the chosen contract applies.

## Progress & Handoff

**Next:** Reproduce the blank-time case and prepare the event representation/association proposal. The association contract needs review.
