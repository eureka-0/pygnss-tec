# T009: Validate navigation selection and merge failures

[Task index](../../ROADMAP.md).

## Objective

Propagate merge errors; apply health/validity/age rules; preserve full station/source identity; quantify reception-time approximations.
For 0.5.0, first prevent invalid broadcast ephemerides from producing apparently valid geometry and accepted TEC.

## Context

Navigation reuse is an architectural task; navigation health/validity/age, merge failures and source identity are a separate correctness contract. No task-order dependency is inferred.

The 2026-10-18 review of `2370e03` used the 2024-01-10 GPS navigation file for 2025-01-10 queries.
It returned finite angles for 31 satellites, five above the default elevation mask, and all 20 rows of a constructed TEC case passed QC.
Nearest reference epoch and finite propagation are therefore insufficient validity checks.
Shared file ingestion already propagates merge errors; preserve that behavior and cover the remaining failure branches rather than duplicating it.

## Scope

`src/calculation/navigation.rs`, `src/calculation/glonass.rs`, `src/io/rinex.rs`, `gnss_tec/io/navigation.py`, `gnss_tec/calculation/observation_geometry.py` and affected reader/navigation/geometry tests and documentation.

## Implementation Plan

1. Add the year-old GPS counterexample and valid neighboring-epoch controls to small navigation/geometry regressions.
   Check the public standalone-angle and RINEX-to-TEC paths, including QC and diagnostic behavior.
2. Inventory parsed health, reference time, toe and fit/validity fields for advertised propagation modes and submit a constellation-specific eligibility table for review.
   Define time scales, boundary inclusivity, missing-field policy and future-record eligibility from the applicable specifications and parser contracts.
   Preserve the validated GLONASS time window and unsupported-SBAS behavior; `NavigationData.epoch_range` is not a per-record validity interval.
   Do not introduce a single guessed age threshold for every constellation.
3. Filter to eligible records before nearest-record selection, preserving existing duplicate/equal-distance rules among eligible candidates.
   An unhealthy or expired nearest record must not hide another eligible record.
   Review unavailable-geometry versus explicit-error behavior and source/SV/query/rejection context before changing the public contract.
4. When no record is eligible, require unavailable geometry or an explicit failure and prohibit accepted TEC.
   Compare valid matched geometry/TEC against the current numerical references and exercise exact validity boundaries and multi-file conflicts.
5. Complete the broader source/station identity and reception-time approximation analysis using independent orbital references.
   The release validity safeguard does not close these remaining acceptance requirements.

## Acceptance Criteria

- [x] The 0.5.0 year-old-navigation case cannot return accepted TEC; standalone angles expose unavailable geometry.
- [x] Eligibility checks cover reviewed health/time/validity boundaries and missing fields; nearest/tie selection is preserved among eligible records.
- [ ] expired, conflicting and unsupported navigation fails with actionable context.
- [ ] Full source/station identity is retained where needed for diagnostics and merging without exposing private helper columns accidentally; reception-time approximations have quantified limits.

## Validation

Exercise current RINEX and multi-day readers, navigation merge conflicts, expiry/health boundaries and independent orbital references. Check actionable error context and geometry availability rather than only absence of crashes.
Include a rejected nearest record with a valid alternative, per-SV gaps, empty selections, duplicate/tied records and GPS/UTC queries.
Use `tests/io/test_navigation.py`, `tests/calculation/test_navigation.py` and `tests/calculation/test_az_el.py` for the corresponding public and native contracts.
