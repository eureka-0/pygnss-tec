# T015: Expose calibrated, leveled and relative TEC products

[Task index](../../ROADMAP.md).

## Objective

Provide explicit calibration status, arc identity, uncertainty and processing provenance; reject unsupported receiver-estimation requests.

## Context

Current outputs already carry some calibration/QC behavior, but the planned full product/uncertainty/provenance contract must be checked against current APIs. Private preparation fields must not leak into public output.

[T028](T028.md) defines the immediate output contract: calibration/QC columns are opt-in diagnostics, geometry remains in default output, and internal leveling/weight/bias-interval columns are never returned. This task must build on that contract; moving diagnostics out of default output does not change the underlying calibration state or establish absolute-TEC validity.

## Scope

`gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/constants.py`, public API.

## Implementation Plan

1. Inventory existing calibrated/partially corrected/no-bias/failure states and public intermediate/diagnostic output policies.
2. Propose explicit absolute/calibrated, leveled and relative product meanings, arc identity, uncertainty and processing provenance, including unsupported estimation requests. Explain product validity without assuming a default per-row `calibration_status` column; any change to T028's exposure contract requires review.
3. Obtain review of the public scientific/schema contract and compatibility path before implementation; update product assembly and configuration boundaries together.
4. Verify no-bias, missing/expired bias, failed estimation and successful calibration independently; document each product's limits and re-run affected examples.

## Acceptance Criteria

- [ ] uncorrected or failed-bias data cannot masquerade as absolute TEC.
- [ ] Failed or unsupported calibration stays explicit and cannot be represented as a silent zero correction or absolute TEC; requested diagnostic rows retain their null-public-TEC policy.

## Validation

Use independent known-TEC/bias controls and API cases covering no bias, partial coverage, estimator failure, unsupported requests and retained diagnostics. Validate schema/dtypes/nulls and product labeling, not just numerical equality.

## Progress & Handoff

**Next:** Inventory current product states and draft the public calibration/uncertainty contract. Product names and schema changes need review.
