# T010: Bound parallelism and eliminate demonstrated rescans

[Task index](../../ROADMAP.md).

## Objective

Profile lazy plans before caching; detach pure Rust work appropriately; add bounded station-level scheduling with coordinated Polars/Rayon/BLAS thread budgets.

## Context

Caching or more parallel workers are not evidence of an optimization. The task requires demonstrated rescans and coordinated Polars/Rayon/BLAS budgets without duplicating large frames.

## Scope

`src/lib.rs`, `gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/bias.py`, `benchmarks/bench.py`.

## Implementation Plan

1. Profile current lazy plans and station workloads; count rescans/materializations and record the actual thread/process environment.
2. Propose caching only for demonstrated reuse, appropriate detachment of pure Rust work, and bounded station scheduling with coordinated thread budgets. Estimate retained-frame lifetime and memory cost.
3. Review any scheduling/ownership architecture change before implementing one measured optimization at a time.
4. Compare serial/bounded scheduling with identical station inputs and scientific outputs; report wall-time, isolated-process RSS and determinism, including large-frame duplication checks.

## Acceptance Criteria

- [ ] measured wall-time/RSS improvement without duplicated large frames or nondeterministic results.
- [ ] Cache/scheduling choices are justified by profiles and retained-memory evidence; scientific results are deterministic under the supported scheduling configurations.

## Validation

Use repeated serial and bounded station runs, fixed thread budgets and matched native builds. Compare identities/dtypes/nulls/numerics, rescan counts and frame retention; consult T001 or define a task-local baseline.

## Progress & Handoff

**Next:** Profile the current lazy plans and thread budgets. No cache or scheduling architecture is selected without evidence.
