# T003: Reuse navigation and unique epoch/SV geometry

[Task index](../../ROADMAP.md).

## Objective

Parse a navigation set once per job; index valid ephemerides per SV; compute geometry once per unique epoch/SV and scatter to long/wide rows.

## Context

Navigation reuse must follow the current reader/preparation interfaces and distinguish shared satellite propagation from receiver-dependent geometry.

## Scope

`src/lib.rs`, `gnss_tec/io/rinex.py`.

## Implementation Plan

1. Inspect navigation ownership and geometry preparation in Rust/Python; count parsing and geometry work for repeated codes and both observation layouts.
2. Propose job-local navigation ownership, valid per-SV ephemeris indexing and a unique epoch/SV geometry key. Account for receiver-specific angle conversion and navigation-set identity; do not share receiver-dependent geometry indiscriminately.
3. Review any public ownership/API change before implementing reuse and scattering geometry to observation rows. Preserve selection errors, row ordering and missing-geometry semantics.
4. Instrument parsing/propagation counts and compare repeated-code, multi-file and multi-receiver results to the unreused reference; record wall-time/RSS where measured.

## Acceptance Criteria

- [ ] parsing counts and geometry counts stay independent of duplicate observation codes.
- [ ] Reuse preserves scientific geometry and receiver history, with missing/expired ephemerides handled as before or under a reviewed contract.

## Validation

Check raw reader, multi-day and GLONASS reference tests; count parsing/epoch-SV propagation separately from per-receiver angles. Compare output identities, coordinates, nulls and TEC against a matched baseline.

## Progress & Handoff

**Next:** Inspect the current preparation path and define reuse ownership/keys. Receiver-dependent geometry and error propagation are constraints to resolve.
