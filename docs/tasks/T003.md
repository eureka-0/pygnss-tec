# T003: Reuse navigation and unique epoch/SV geometry

[Task index](../../ROADMAP.md).

## Objective

Parse a navigation set once per job; index broadcast ephemerides per SV; propagate once per unique epoch/SV and scatter receiver-dependent angles to long/wide rows.

## Context

Navigation reuse must follow the current reader/preparation interfaces and distinguish shared satellite propagation from receiver-dependent geometry.

## Scope

`src/lib.rs`, `src/calculation/navigation.rs`, `gnss_tec/io/navigation.py`, `gnss_tec/calculation/observation_geometry.py`, shared time helpers, public TEC entry points, affected tests/benchmarks and README/Zensical documentation.

## Implementation Plan

1. Freeze the pre-change source/native build, reference geometry/TEC and matched performance inputs.
2. Implement the reviewed immutable native navigation store with per-SV indexes and Arrow query columns; retain the existing nearest-record/tie and propagation rules.
3. Expose `read_rinex_nav`, `NavigationData` and `compute_az_el`, separating coordinate resolution from TEC event-state preparation and preserving input rows/times.
4. Directly rename TEC entry points to `compute_tec`, `compute_tec_from_parquet` and `compute_tec_from_rinex`; remove old exports without aliases or deprecation wrappers.
5. Validate reuse/query counts, repeated-code and receiver-history behavior, full outputs, clean-wheel imports, README/Zensical examples and matched timing/RSS.

The user reviewed the detailed plan and selected the final names, direct migration and limited documentation updates before authorizing implementation on 2026-10-17.
Navigation health/age rules remain T009 work; this delivery preserves current selection behavior.
