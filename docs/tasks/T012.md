# T012: Extend Galileo, GPS/BDS multi-frequency and GLONASS TEC

[Task index](../../ROADMAP.md).

## Objective

Add systems incrementally; GLONASS FDMA uses per-SV channel frequencies and bias conventions.

## Context

GLONASS geometry and FDMA TEC support are distinct capabilities. The requested extensions use the versioned signal/adapter contract; the prerequisite is recorded in the main task table.

## Scope

signal registry, `src/lib.rs`, `gnss_tec/tec/tec_calculation.py`, tests.

## Implementation Plan

1. After confirming the registry/adapters are available, choose incremental released modes and specify per-SV channel frequency/bias handling and orbital regimes for each.
2. Obtain review of support/bias conventions, especially GLONASS FDMA and BDS GEO/IGSO where advertised; do not enable a mode on the basis of code names alone.
3. Implement and validate one signal/system mode at a time through registry, native geometry and TEC assembly, retaining explicit unsupported-mode behavior.
4. Publish support only with independent known-TEC and orbit evidence for that mode; record any excluded regimes and calibration limitations.

## Acceptance Criteria

- [ ] independent known-TEC and orbital references for each released mode, including BDS GEO/IGSO where advertised.
- [ ] GLONASS TEC uses per-SV FDMA channels and explicit bias conventions; advertised BDS GEO/IGSO modes have their own orbital evidence.

## Validation

Use pair-specific injected known TEC and independent orbit/channel references for Galileo, GPS/BDS multi-frequency and GLONASS modes as released. Cross-check code-bias signs and unsupported-channel behavior.

## Progress & Handoff

**Next:** Confirm the registry prerequisite and draft the first incremental support/bias proposal. Geometry availability is not proof of TEC support.
