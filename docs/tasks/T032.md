# T032: Interpret flag-6 events by satellite and phase signal

[Task index](../../ROADMAP.md).

## Objective

Decode retained flag-6 payloads into satellite/phase-specific evidence and restrict their effects to the applicable observation streams when interpretation is reliable.
Preserve the original metadata and conservative fallback when scope or meaning is unknown.

## Context

R01 prevents event payload values from overwriting observations.
R04 conservatively makes a flag-6 event a station-level reset epoch.
At `1b9130f`, `_prepare_observations` still builds a shared event-state timeline rather than satellite/phase-specific targets.
The RINEX format can report detected or repaired slips, so a recorded number is not automatically an unapplied correction.

T031 supplies the effective version/header field context required when observation-code order or phase conventions change.
Static-header fixtures can be designed independently, but complete supported-input acceptance must use that effective context.
The completed T030 policy aligns localized time discontinuities and does not resolve carrier integers.

## Scope

Event parsing in `src/io/quality.rs`/native ingestion, retained RINEX metadata, `gnss_tec/calculation/observation_geometry.py`, `gnss_tec/signals/arcs.py` and `src/signals/arcs.rs`.
Integrate scoped evidence with existing basic/detect/repair modes; do not turn event payloads back into normal observations or reopen numeric repair design.

## Implementation Plan

1. Review version-specific flag-6 framing and value semantics against the applicable RINEX 2/3 specifications, including satellite lists/continuations and phase columns.
   Use T031's effective observation order, units and wavelength context; define blank, zero, malformed, duplicate and unknown records explicitly.
2. Submit an internal event model and behavior table for human review before implementation.
   Include epoch/source order, station, satellite, phase-observation identity and raw reported value/meaning.
   Distinguish known targets, already-repaired reports and unknown scope; resolve same-time and duplicate-report behavior.
3. Match reliable evidence to the selected phase pair at the reviewed event boundary.
   A G01/L1 event must not reset G02 merely because the epoch is shared; an event on an unselected phase follows the reviewed signal-scope policy.
   Independent receiver/site/power/LLI evidence keeps its normal reset effect.
4. Replace global flag-6 state increments only where targeting and interpretation are supported.
   Retain explicit conservative fallback for incomplete payloads, unknown phase conventions and row-level flags without targeting metadata.
   Preserve explicit receiver state, blank-epoch omissions and observation/event separation.
5. Supply scoped boundary evidence to existing arc/localization processing and retain mode-specific behavior.
   Never subtract the payload number directly from observations or apply a second correction for an already-repaired report.
   Reconcile event/LLI/detector reports at one boundary without suppressing independent evidence.
6. Verify affected/unaffected streams and final public products in all three modes, then document event scope, effective-time rules and unsupported cases.

## Acceptance Criteria

- [ ] Supported payloads resolve the intended satellite and phase observation under the effective RINEX 2/3 header; raw observations and event metadata remain intact.
- [ ] Unaffected satellites and independently unaffected selected signals retain continuity; actual targeted slips and independent receiver resets still produce the reviewed behavior.
- [ ] Unknown/malformed scope or standalone flags retain explicit conservative fallback, not silently ignored evidence or an invented target.
- [ ] Header changes, same-time records, compression, multiple files and metadata round trips preserve targeting and Python/native equivalence.
- [ ] Already-repaired and duplicate reports never cause unconditional or double correction; the delivered continuity estimator and immutable raw-observation contract remain intact.

## Validation

Construct multi-satellite/multi-signal files where only one phase carries a flag-6 report.
Check affected/unaffected arc identities, raw values, derived TEC and event retention in basic/detect/repair modes.
Include active header-order changes, continuations, blanks/zeros, incomplete and conflicting reports, standalone DataFrame flags and already-repaired phase controls.
Verify both layouts and LLI settings; never substitute slip payload values for observations.
