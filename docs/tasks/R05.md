# R05: Evaluate GF/MW detection and small-slip sensitivity

[Task index](../../ROADMAP.md).

## Objective

Quantify the accuracy, sensitivity and runtime tradeoff of rolling geometry-free (GF) and Melbourne–Wübbena (MW) detection. Explore a high-performance implementation with [T005](T005.md), preserving genuine TEC changes and raw carrier phase.

## Context

The user selected basic QC as the default on 2026-10-13. Rolling GF/MW detection is currently disabled. This task records the detectors for further study; it does not restore them or change defaults.

The planned behavior detects candidate discontinuities and starts separate arcs for leveling. It does not estimate per-carrier ambiguity jumps or numerically repair phase observations. Such repair has no approved task or delivery date; it would require a separate scientific contract and validation plan.

The historical reference is `aac8884:gnss_tec/tec/quality.py`. GF uses the median of prior phase-TEC slopes to predict the next phase increment. MW uses the median and median absolute deviation (MAD) of prior MW increments. The shared statistics helper also calculated GF MAD, but GF did not use it. These are project-specific decision rules, not a claim that every GF/MW detector uses median/MAD.

For the 30 s sample, the reference uses 10 prior epochs, a 2 TECU GF innovation threshold scaled by `max(1, dt/cadence)`, and an MW threshold of `max(0.75 cycles, 6 * 1.4826 * MAD)`. At sampling intervals up to 5 s, the GF threshold is 0.5 TECU and the window is 20 epochs. An MW jump starts a new arc. A GF jump without an MW jump is retained only when MW history is sufficiently stable and the code-derived TEC change agrees; otherwise it starts an uncertain arc. Neither detector rewrites phase.

### Measured result and runtime impact

Controlled comparison on 2026-10-13: CIBG `CIBG00IDN_R_20240100000_01D_30S_MO.rnx.gz`, BRDC navigation and CAS DCB products for 2024 day 010; 180,027 resident rows with geometry, 101,663 GPS/BeiDou rows entering TEC, and 50,315 accepted output rows. Python 3.14.8, Polars 2.0.0, in-memory engine, 12 threads, one warmup and seven serial repetitions in alternating order. Timings include the complete default TEC call and collection, including bias reads/validation, and exclude observation decoding and geometry preparation. Diagnostic fields were collected outside timing.

The same current selection, geometry, mapping and leveling code was used in all variants. Only the arc implementation was substituted. The Python basic control disables both rolling-statistics calculations and the GF/MW decision branch in the historical reference; its output matches native basic QC at `rel_tol=0, abs_tol=1e-8`. Native build SHA-256: `f443c810a80b43db77e780ef4eb18b1a2280a91436f3bfa02db9f8bd22054de7`.

The 0.4169 s difference from native basic QC also includes Python state-loop and conversion overhead; it must not all be attributed to rolling statistics. Earlier approximately 0.95 s TEC benchmarks also included the old candidate-expansion path.

The four additional boundaries were all labelled `mw_slip`; this sample produced no additional GF-labelled boundary. Time/station/PRN identities, selected pairs, accepted row count and raw phase are unchanged. Changed rows use absolute differences greater than `1e-8` TECU.

These are algorithm differences, not accuracy errors against independent truth. The real sample does not establish whether the four MW detections are true slips or false alarms. Added boundaries change the samples contributing to each code-to-phase leveling offset, which explains differences across more rows than the four event epochs. Accuracy improvement and false-positive costs remain to be measured.

The physical combinations and their limitations are described in ESA Navipedia's [GF detector](https://gssc.esa.int/navipedia/index.php?title=Detector_based_in_carrier_phase_data%3A_The_geometry-free_combination) and [MW detector](https://gssc.esa.int/navipedia/index.php?title=Detector_based_in_code_and_carrier_phase_data%3A_The_Melbourne-W%C3%BCbbena_combination). GF contains real ionospheric variation; MW is affected by code noise/multipath and is insensitive to equal cycle jumps on both carriers.

## Scope

`gnss_tec/signals/arcs.py`, `gnss_tec/configuration.py`, `tests/test_cycle_slip.py`, scientific comparison assets, and the native-kernel boundary covered by T005.

## Implementation Plan

1. Reproduce the reference and basic-QC comparison. Add GF-only, MW-only and joint ablations with explicit definitions of MW's auxiliary role in the GF decision, so costs and event changes can be attributed correctly.
2. Define reproducible 1/5/30 s cadence and noise/multipath controls with known TEC and ambiguity changes. Include 0.5-cycle single-band, simultaneous 1-cycle dual-band, GF-cancelling slips, no-slip noise, rapid genuine TEC changes and short histories after resets. Record ranges, seeds and event/sample denominators.
3. Measure missed/false detections and STEC/VTEC bias, RMS and maximum error against independent truth. Separate those accuracy results from real-data algorithm differences. Verify gaps, receiver/events, rejected rows and signal switches reset history correctly, and midnight alone does not.
4. Evaluate adaptive GF/MW/LLI evidence against the same controls before lowering thresholds. Treat improved slip sensitivity with damaged genuine TEC variation or excessive false splits as a failed tradeoff.
5. With T005, compare exact small-window native statistics, reused increments and per-group state against the reference. Record isolated detection cost, complete TEC-call latency and memory, including conversion/materialization. The proposed performance target is a complete enabled TEC-only path below 0.1 s on the resident CIBG sample under the recorded settings; validate it rather than assuming Rust alone will achieve it.
6. Document the supported detection envelope and accuracy/runtime tradeoff. Obtain review before integration or changing scientific thresholds/defaults; preserve raw phase and the selected default basic-QC policy until such a change is approved.

## Acceptance Criteria

- [ ] GF, MW and joint variants have independent-truth accuracy and detection measurements across the justified matrix; existing 5-cycle cases do not establish half-cycle sensitivity.
- [ ] Real-data differences and accuracy errors are distinguished, with row/event denominators, changes to arc/leveling state and retained/rejected samples reported.
- [ ] Raw phase and rapid genuine TEC variation remain preserved; equal-band and GF-cancelling slips are explicitly covered.
- [ ] High-performance candidates have matched scientific results and measured isolated/full-call cost including conversions. Record all seven CIBG timings and whether the proposed 0.1 s target is met; do not weaken validation to meet it.
- [ ] Default or threshold changes follow review of the measured tradeoff, with user-facing QC behavior documented concisely.

## Validation

Use independent physical controls and existing cycle-slip, multi-day, bias and diagnostic-output regressions. Real measurements need multiple stations/days and signal pairs; the single CIBG result does not establish a universal accuracy gain. Compare identities, schema, null masks and raw phase before numerical error metrics. Pin inputs, native build, engine/thread settings and timing boundaries; keep any reproducibility harness separate from the generated `benchmarks/benchmark.md` tables.
