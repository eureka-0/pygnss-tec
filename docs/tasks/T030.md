# T030: Estimate and repair integer cycle slips with fallback

[Task index](../../ROADMAP.md).

## Objective

Estimate supported carrier-phase integer jumps and compensate a separate working phase/TEC path. After independent validation, enable high-confidence integer repair by default; uncertain cases retain conservative arc splitting. Preserve every raw observation.

## Context

R01–R04 delivered input/event handling and basic QC in `d7dbbcb`. They do not estimate slip magnitudes. R05 owns candidate detection and its independent scientific reference; this task owns integer estimation, correction, uncertainty/fallback and effective continuity. T005 owns equivalent native execution and performance.

The user selected the eventual default-repair policy on 2026-10-15. This approves the target, not an unspecified algorithm, confidence threshold or public schema. These decisions need review before implementation. Current defaults remain unchanged until the acceptance gates pass.

## Scope

Initially cover supported dual-frequency GPS/BeiDou inputs only where phase units, tracking identity and wavelength factors are unambiguous. Use `gnss_tec/signals/`, `gnss_tec/calculation/tec.py`, configuration, native boundaries where justified, diagnostic selection and independent physical tests. Preserve the existing reader/raw-column meanings. Half-cycle repair, bridging receiver/site/frequency changes and inventing phase across missing observations are outside the initial scope.

## Proposed Scientific and Output Contract

- Detection is evidence of a possible discontinuity, not a known jump. For a defined positive jump, estimate integers `n1`, `n2`; apply `L1_work = L1_raw - cumulative_n1` and `L2_work = L2_raw - cumulative_n2`, using actual wavelengths/frequencies and an explicitly tested sign convention.
- As a candidate model for review, combine a predicted geometry-free residual in metres (`lambda1*n1 - lambda2*n2` after genuine TEC evolution) with the MW residual in cycles (`n1 - n2`) and available code/phase evidence. Estimate uncertainty and compare multiple integer candidates; do not blindly round one noisy combination or remove every GF step.
- Correct only uniquely supported candidates within a reviewed validation envelope. Unknown phase conventions, half-cycle indicators, insufficient history, conflicting evidence and receiver/site/signal/frequency transitions require the documented rejection/reset path. Define gap handling and limits explicitly; do not infer a trustworthy integer count across unobserved data.
- Keep raw phases, `stec_p_raw` and physical `arc_id` semantics intact. Review an internal effective continuity/repair state for the corrected phase and leveling. Subtracting a constant and then independently re-leveling every physical arc can cancel the correction, so validate the complete repaired TEC path. Bias-validity intervals remain separate and are never bridged merely because repair succeeds.
- Expose repair attempts, per-carrier estimates, accepted/rejected reasons and uncertainty through reviewed diagnostics selectable by `retain_diagnostics`. Preserve the default geometry/output contract and keep internal leveling fields private. Review exact names and an explicit basic/no-repair mode; do not add undocumented schema changes.
- RINEX flag-6 records can report detected or already-repaired slips. Their values are evidence requiring interpretation, not instructions to subtract a count again. Coalesce duplicate LLI/GF/MW/event reports and demonstrate that already-corrected observations are never corrected twice.

3. Implement an isolated Float64 reference estimator and cumulative-correction state using the reviewed single-receiver dual-frequency model. 4. Verify both per-carrier integer estimates and complete corrected phase/TEC against no-slip truth. The user has approved this eventual policy; algorithm/API and validation review still apply. ## Acceptance Criteria

- [ ] Supported integer jumps are recovered per carrier and corrected phase/TEC match independent no-slip truth under the reviewed envelope, including simultaneous and repeated slips.
- [ ] False accepted repairs, missed events and rejected/ambiguous attempts are measured separately. Rapid genuine TEC, no-slip noise and code outliers are not flattened into artificial continuity.
- [ ] Uncertain cases split without numerical repair; unsupported half-cycle/version/frequency states and receiver/site changes cannot be silently stitched.
- [ ] Raw observations, raw-phase TEC and physical arc identity remain traceable; effective repair continuity and bias intervals obey the reviewed model. Already-repaired/duplicate reports cannot cause double correction.
- [ ] DataFrame/RINEX/Parquet inputs and partition/multi-file boundaries agree on correction, diagnostics, rejection and fallback; the basic/no-repair mode reproduces the frozen baseline.
- [ ] Reference/native equivalence and end-to-end correctness/performance are checked. Validated integer repair becomes the default only after the specified gates pass, with documented uncertainty fallback and public API changes.

## Validation

Use R05's 1/5/30 s truth/noise matrix, current physical/multi-day/bias regressions and recorded-event fixtures. Include normal tracking, loss-of-lock evidence, false alarms, candidate ties, wavelength-factor ambiguity, header updates and already-corrected flag-6 reports. Validate integer labels as well as TEC residuals; visual smoothness or lower arc counts alone are insufficient. Set acceptance thresholds before candidate evaluation. Scientific evidence belongs in tests/technical reports, with inputs, native build and runtime settings recorded there.
