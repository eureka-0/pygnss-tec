# T008: Separate geometric IPPs from mapping models

[Task index](../../ROADMAP.md).

## Objective

Define Earth model, receiver height, latitude convention and MSLM parameters; support an independently tested ECEF shell intersection.

## Context

Ray/shell geometry and empirical mapping models require separate coordinate and parameter contracts.

## Scope

`gnss_tec/tec/mapping_func.py`, `gnss_tec/tec/constants.py`, `gnss_tec/rinex/read_rinex.py`.

## Implementation Plan

1. Inspect current IPP/mapping inputs and coordinate metadata; separate physical ray/shell geometry from empirical MSLM mapping parameters.
2. Specify Earth model, height reference, geocentric/geodetic latitude, shell intersection and longitude conventions. Compare proposed ECEF geometry with current behavior and identify API/scientific compatibility effects.
3. Obtain review of the geometry/mapping contract before implementation; implement ECEF intersection independently of mapping-model selection.
4. Validate against an independent geometric reference, preserving polar/antimeridian/zenith cases and reporting shell-height sensitivity and coordinate metadata.

## Acceptance Criteria

- [ ] explicit coordinate metadata and shell-height sensitivity results.
- [ ] Geometric coordinates and empirical mapping parameters are separately documented; shell-height sensitivity is quantified rather than hidden in defaults.

## Validation

Use independent ECEF shell calculations, both hemispheres, receiver heights, polar/antimeridian paths and zenith controls. Compare coordinate residuals and TEC mapping sensitivity across justified shell heights.

## Progress & Handoff

**Next:** Inventory current geometry conventions and draft the reviewed coordinate/mapping contract. No new Earth model or shell height is assumed.
