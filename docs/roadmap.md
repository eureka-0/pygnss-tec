# PyGNSS-TEC Project Roadmap

This roadmap guides the development of PyGNSS-TEC as a reliable scientific library for GNSS observations and ionospheric products. It covers scientific correctness, data integrity, architecture, scalability, signal and product support, user workflows, documentation and releases.

Initial planning baseline: `0.4.2`, commit `fd94ce07f475fde8553413616b72da920cb66059`, reviewed 2026-10-09. Paths below are repository-relative. Unchecked tasks are planned work; update their scope, priority and acceptance criteria as the project evolves.

Priorities: **P0** scientific correctness or supported-input blockers; **P1** core reliability, architecture and scalability; **P2** scientific capabilities and user workflows; **P3** long-term quality and release readiness. Phases express the current implementation order, not fixed release dates. Tests and documentation accompany each change; Phase 4 extends those practices across the project.

## Phase 1: Scientific Correctness and Data Integrity — P0

- [x] **P0 · Preserve observation quality and epoch state.** Files: `src/lib.rs`, `src/quality.rs`, `gnss_tec/_core.pyi`, `gnss_tec/rinex/read_rinex.py`, `tests/test_rinex_quality.py`. Export original per-signal LLI and epoch flags in both table layouts; preserve receiver identity, positions and event records in header metadata. TEC derives half-cycle validity and receiver/event state internally; preserve flags through filtering. Acceptance: minimal RINEX 2/3 fixtures retain every injected flag.
- [x] **P0 · Replace unconditional cycle-slip flattening.** Files: `gnss_tec/tec/quality.py`, `gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/constants.py`, `tests/test_cycle_slip.py`, `tests/test_polars_compat.py`. Combine LLI, cadence-aware GF innovations and robust MW evidence; split uncertain arcs and retain raw phase/QC reasons. Acceptance: flagged half-cycle cases and tested early, simultaneous and repeated slips are handled without removing injected ionospheric changes; unflagged small-slip sensitivity remains a separate validation task.
- [x] **P0 · Make arc boundaries respect signal and receiver state.** Files: `gnss_tec/tec/quality.py`, `gnss_tec/tec/tec_calculation.py`, `gnss_tec/rinex/read_rinex.py`, `tests/test_multiday.py`. Include signal-pair changes, reacquisition and receiver resets; retain continuity across midnight only when justified. Acceptance: code switches create a new ambiguity segment; unchanged continuous signals remain continuous.
- [x] **P0 · Correct external code biases before phase leveling.** Files: `gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/bias.py`, `tests/test_tec_bias.py`, `tests/test_multiday.py`. Separate physical arcs from bias/leveling intervals; avoid double subtraction. Acceptance: constant 30 TECU with daily 1/2 TECU code biases stays 30 TECU across midnight.
- [x] **P0 · Enforce bias kind, units, time scale and validity.** Files: `gnss_tec/tec/bias.py`, `gnss_tec/tec/signals.py`, `tests/test_bias.py`, `tests/test_tec_bias.py`. Preserve product metadata; initially accept supported code DSB/ns/GPS inputs and reject unsupported semantics; match start/end intervals and reject overlaps explicitly. Acceptance: daily/subdaily/monthly, expired, reverse-pair and wrong-unit cases; preserve the existing correct DSB sign.
- [x] **P0 · Reject invalid numerics and frequency pairs before aggregation.** Files: `gnss_tec/tec/constants.py`, `gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/bias.py`, `tests/test_config.py`, `tests/test_observation_quality.py`, `tests/test_polars_compat.py`. Validate finite observations/geometry/configuration, positive distinct frequencies, valid times and weight support; retain rejection reasons. Acceptance: one NaN/Inf cannot poison valid arc samples; same-frequency pairs fail clearly.
- [x] **P0 · Select complete code-and-phase pairs with explicit fallback.** Files: `gnss_tec/tec/signals.py`, `gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/constants.py`, `tests/test_observation_quality.py`, `tests/test_polars_compat.py`. Score joint P1/L1/P2/L2 availability and bias coverage; document the priority rule; split arcs when switching pairs. Acceptance: C1W without L1W does not discard usable C1C/L1C observations.
- [x] **P0 · Fix IPP longitude quadrants and wrapping.** Files: `gnss_tec/tec/mapping_func.py`, `tests/test_mapping_func.py`. Use atan2, bounded inverse-trigonometric inputs and explicit longitude normalization. Acceptance: polar crossing, antimeridian, zenith and both hemispheres match independent geometry.
- [x] **P0 · Preserve fractional sampling intervals and epoch precision.** Files: `src/lib.rs`, `src/quality.rs`, `gnss_tec/_core.pyi`, `gnss_tec/rinex/read_rinex.py`, `tests/test_rinex_time.py`, `tests/test_config.py`. Keep floating-point interval seconds; adopt an explicit integer epoch resolution and metadata round-trip. Acceptance: a real 0.1 s RINEX header remains 0.1 s and completes TEC processing; unsupported precision is never silently collapsed.
- [x] **P0 · Repair advertised GLONASS geometry propagation.** Files: `src/glonass.rs`, `src/lib.rs`, `Cargo.toml`, `Cargo.lock`, `tests/test_glonass_propagation.py`, `tests/test_multiday.py`. Propagate broadcast state to the requested epoch through a validated implementation; otherwise mark geometry unavailable. Acceptance: off-reference-epoch positions match an independent reference and no longer remain artificially constant between ephemerides.

### Review follow-ups — 2026-10-12

The completed items above describe the implemented baseline, not closure of every boundary case. The following review findings reopen the Phase 1 exit gate; P1/P2 labels indicate follow-up urgency. Each item includes its implementation target and acceptance criteria.

- [ ] **P1 · R01: Keep cycle-slip event records out of observation values.** Files: `src/lib.rs:138–175`, `src/quality.rs`, `tests/test_rinex_quality.py`. Separate flag-6 payloads from normal observations in both layouts and retain their event meaning. Acceptance: a same-epoch flag-6 L1 slip count of 5 never replaces the normal 110355719.242-cycle observation or creates duplicate observation keys. The epoch/SV overwrite mechanism predates this change set.
- [ ] **P2 · R02: Prefer usable signal pairs before applying priorities.** Files: `gnss_tec/tec/signals.py:154–199`, `tests/test_observation_quality.py`. Include phase validity and the existing SNR policy in candidate eligibility; preserve diagnostics when no candidate is usable. Acceptance: invalid-half-cycle C1W/L1W falls back to valid C1C/L1C, retaining all 20 synthetic epochs; loss-of-lock alone remains an arc boundary, not automatic sample rejection.
- [ ] **P2 · R03: Preserve special events with blank epoch fields.** Files: `src/quality.rs:65–111`, header metadata, `tests/test_rinex_quality.py`. Parse flags/counts by RINEX field positions; retain untimed records and define their association with surrounding observations without inventing timestamps. Acceptance: legal blank-time flag-4 records survive reading and metadata round-trip, with unchanged observation values/counts.
- [ ] **P2 · R04: Distinguish metadata events from ambiguity resets.** Files: `gnss_tec/tec/preparation.py:84–107`, `gnss_tec/tec/quality.py:92–94`, `tests/test_cycle_slip.py`. Classify event contents before changing ambiguity state; preserve general events without forcing a reset. Acceptance: COMMENT-only flag 4 and non-reset flag 5 do not split continuous phase; the constant-30-TECU/code-noise fixture stays at 30 rather than acquiring a 29/31-TECU leveling step, while actual resets still split arcs.

**Exit gate:** Existing regressions and all new independent physical counterexamples pass, including R01–R04. Published results expose calibration/QC status; unsupported or failed calibration cannot silently become a zero correction. Review status: the tracked suite passes 216 tests; four additional review probes fail and are documented in the consolidated report.

Implemented baseline verified locally on 2026-10-12: Python 3.14.8 / PyArrow 26.0.0, with 216 tests passing on each of Polars 1.40.0 and 2.0.0. All 88 test collection calls explicitly use `engine="in-memory"`; a session fixture also selects in-memory for internal library validation queries. The suite and CI no longer repeat cases for streaming, while retaining the Python/Polars version matrix. Content-specific test modules retain independent physical and boundary assertions, including forward/backward GLONASS comparisons against DOP853 and unavailable expired geometry. Ruff, formatting, ty, `cargo test --locked` and macOS `cargo check --locked --all-features` pass. Default output drops QC-rejected samples; only `retain_intermediate="all"` keeps diagnostic rows with null public TEC and rejection reasons. Cross-platform checks remain in the existing CI matrix.

The reader now returns only raw observation values, LLI, epoch flags and identifiers in both pivot layouts. Observation-code filters use case-sensitive regular-expression full matches. Navigation input belongs to the TEC APIs; private preparation columns never appear in their outputs, while explicitly requested TEC intermediates and rejected diagnostic rows remain supported. Header receiver history preserves positions/identities across daily files and Parquet round-trips. README tables are copied from actual Polars terminal output; a matched before/after geometry and TEC comparison is recorded in `benchmarks/benchmark.md`.

Regression sample selection follows each assertion's purpose. Full samples remain for all-signal RINEX/Hatanaka decoding, four receivers' complete two-day reader comparisons, two-day GLONASS navigation, whole-day GPS/BeiDou TEC equivalence (50,315 rows) and MSTD/LSQ receiver estimation. Native individual-file inputs are parsed once and their full queries execute with in-memory; both receiver-estimation methods share one whole-day observation frame. Focused QC, bias-boundary, API and output-policy checks retain small physical samples or real midnight/nighttime windows.

The local regression budget is less than 5 GB peak RSS (5,000,000,000 bytes) and 60 seconds wall time per complete pytest process with dependencies already installed. On macOS with Python 3.14.8, PyArrow 26.0.0 and 12 threads, all 216 tests pass in 39.59 seconds / 1,821,310,976 bytes (1.82 GB) peak RSS on Polars 2.0.0 and 40.57 seconds / 2,465,218,560 bytes (2.47 GB) on Polars 1.40.0. Time includes the uv/pytest process startup; dependency installation is outside this budget. These measurements describe the local regression suite; production full-RINEX processing and hosted CI remain separate measurements.

The test engine is explicit because Polars 2.0 defaults to streaming, whereas 1.40 defaults to in-memory. An isolated comparison using the same pre-parsed 101,663-row whole-day GPS/BeiDou input, 12 threads, one warmup and seven serial repetitions produced 50,315 equivalent TEC rows in all six version/engine combinations (all columns, relative tolerance 0, absolute tolerance 1e-8). Median calculation times for in-memory/streaming were 0.82/1.17 seconds on 2.0 and 0.83/1.19 seconds on 1.40. Whole-arc state, sorting and joins make streaming performance and peak RSS workload-dependent; this test policy does not change the library's engine selection.

## Phase 2: Core Architecture, Reliability and Scalability — P1

- [ ] **P1 · R05: Quantify unflagged small-slip sensitivity.** Files: `gnss_tec/tec/quality.py`, `gnss_tec/tec/constants.py`, `tests/test_cycle_slip.py`. Add 0.5-cycle single-band and simultaneous 1-cycle dual-band cases across cadence/noise regimes; document the detection envelope and evaluate adaptive evidence before lowering thresholds. Acceptance: report misses and false positives while preserving rapid genuine TEC changes; existing 5-cycle cases do not establish half-cycle sensitivity.
- [ ] **P1 · Establish stage and memory baselines.** Files: `benchmarks/bench.py`, `benchmarks/benchmark.md`. Measure decompression, parsing, navigation, pivot, geometry, QC, leveling, bias and export; record isolated-process peak RSS, input hashes, native build hash and thread counts. Acceptance: repeatable 1/30 s, single/multiple-day and multiple-station cases with scientific comparisons.
- [ ] **P1 · Push required observation columns into the reader.** Files: `gnss_tec/tec/tec_calculation.py`, `gnss_tec/rinex/read_rinex.py`, `src/lib.rs`. Read complete candidate signal sets and QC fields; avoid loading unused Doppler/other signals for TEC. Acceptance: identical accepted measurements with lower measured memory and parse/pivot cost.
- [ ] **P1 · Reuse navigation and unique epoch/SV geometry.** Files: `src/lib.rs`, `gnss_tec/rinex/read_rinex.py`. Parse a navigation set once per job; index valid ephemerides per SV; compute geometry once per unique epoch/SV and scatter to long/wide rows. Acceptance: parsing counts and geometry counts stay independent of duplicate observation codes.
- [ ] **P1 · Introduce genuinely bounded input batches.** Files: `src/lib.rs`, `gnss_tec/rinex/read_rinex.py`, `gnss_tec/tec/tec_calculation.py`. Evaluate incremental RINEX decoding before adding RecordBatch streaming; retain cross-batch arc state or use two-pass leveling; partition intermediate Parquet. Acceptance: bounded peak RSS as duration grows, with no chunk-boundary TEC steps.
- [ ] **P1 · Move stateful arc kernels out of Python hot loops.** Files: `src/lib.rs`, `gnss_tec/_core.pyi`, `gnss_tec/tec/tec_calculation.py`. Keep columnar candidate detection; implement validated linear-time per-arc state machines and minimize NumPy/Polars conversions. Acceptance: physical equivalence and a measured throughput improvement on long/high-rate arcs.
- [ ] **P1 · Stabilize and accelerate receiver-bias estimation.** Files: `gnss_tec/tec/bias.py`, `tests/test_polars_compat.py`. Check epoch support, matrix rank/conditioning and solver status; center/scale features; precompute MSTD sufficient statistics; return uncertainty and failure reasons. Acceptance: recover identifiable known biases and reject single-SV/constant-mapping degeneracies.
- [ ] **P1 · Make SNR filtering and leveling robust.** Files: `gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/constants.py`. Separate missing-SNR policy from low-SNR rejection; use robust code-phase offsets and report support/residual statistics. Acceptance: unrelated satellites cannot alter existing QC decisions; code outliers do not shift a whole valid arc unchecked.
- [ ] **P1 · Separate geometric IPPs from mapping models.** Files: `gnss_tec/tec/mapping_func.py`, `gnss_tec/tec/constants.py`, `gnss_tec/rinex/read_rinex.py`. Define Earth model, receiver height, latitude convention and MSLM parameters; support an independently tested ECEF shell intersection. Acceptance: explicit coordinate metadata and shell-height sensitivity results.
- [ ] **P1 · Validate navigation selection and merge failures.** Files: `src/lib.rs`, `gnss_tec/rinex/read_rinex.py`, `tests/test_rinex.py`. Propagate merge errors; apply health/validity/age rules; preserve full station/source identity; quantify reception-time approximations. Acceptance: expired, conflicting and unsupported navigation fails with actionable context.
- [ ] **P1 · Bound parallelism and eliminate demonstrated rescans.** Files: `src/lib.rs`, `gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/bias.py`, `benchmarks/bench.py`. Profile lazy plans before caching; detach pure Rust work appropriately; add bounded station-level scheduling with coordinated Polars/Rayon/BLAS thread budgets. Acceptance: measured wall-time/RSS improvement without duplicated large frames or nondeterministic results.

**Exit gate:** Report throughput, peak RSS, retention/QC changes and independent scientific residuals together. Set regression budgets from stable measurements; changing the Polars engine alone is not a streaming-input implementation.

## Phase 3: Scientific Capabilities and User Workflows — P2

- [ ] **P2 · Add a versioned signal registry and RINEX 2 adapters.** Files: `gnss_tec/tec/constants.py`, `gnss_tec/tec/tec_calculation.py`, new signal module. Validate constellation/version/tracking combinations; support P1/P2 and explicit P1-C1/P1-P2 bridges without guessing tracking identity. Acceptance: every supported pair has frequency, phase-partner and bias tests.
- [ ] **P2 · Extend Galileo, GPS/BDS multi-frequency and GLONASS TEC.** Files: signal registry, `src/lib.rs`, `gnss_tec/tec/tec_calculation.py`, tests. Add systems incrementally; GLONASS FDMA uses per-SV channel frequencies and bias conventions. Acceptance: independent known-TEC and orbital references for each released mode, including BDS GEO/IGSO where advertised.
- [ ] **P2 · Normalize DSB/OSB products and add product retrieval.** Files: `gnss_tec/tec/bias.py`, new product I/O/cache modules. Support reverse pairs, validated bias chains and OSB differences; retrieve supported IGS/CAS/CODE/GFZ products with provenance, checksums, retries and offline caching. Acceptance: reproducible product selection with no silent overlap or datum mixing.
- [ ] **P2 · Add IONEX ingestion and comparison utilities.** Files: new IONEX/product modules, tests, documentation. Preserve epoch, height, exponent, RMS, longitude wrapping and missing cells; align slant/vertical comparisons explicitly. Acceptance: interpolation fixtures and traceable GIM comparisons without treating GIM as local-ray truth.
- [ ] **P2 · Expose calibrated, leveled and relative TEC products.** Files: `gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/constants.py`, public API. Provide explicit calibration status, arc identity, uncertainty and processing provenance; reject unsupported receiver-estimation requests. Acceptance: uncorrected or failed-bias data cannot masquerade as absolute TEC.
- [ ] **P2 · Offer an optional causal Hatch mode.** Files: new leveling module, `gnss_tec/tec/constants.py`, tests. Define window/time constant, irregular-cadence behavior, reset/warm-up state and code-carrier divergence assumptions. Acceptance: analytic ramp/noise/slip cases and clear distinction from offline arc leveling.
- [ ] **P2 · Add ROT/ROTI and qualified scintillation products.** Files: new index/QC modules, tests. Use same-arc STEC differences, explicit TECU/min, cadence and window coverage; gate S4/sigma-phi behind suitable intensity/high-rate phase inputs and documented detrending. Acceptance: reject insufficient ordinary low-rate RINEX inputs for standard scintillation claims.
- [ ] **P2 · Standardize export metadata and add Xarray/NetCDF.** Files: `gnss_tec/rinex/read_rinex.py`, new export modules, tests. Extend existing Parquet support with partitions/QC/provenance; add dimensionally valid Xarray/NetCDF output and optional HDF5 only when needed. Acceptance: units, time scale, coordinates, flags and calibration metadata survive round-trip.
- [ ] **P2 · Add a CLI that delegates to the library.** Files: `pyproject.toml`, new CLI module, `README.md`. Expose read/TEC/QC/export commands with shared configuration, explicit missing-bias policy and meaningful exit codes. Acceptance: CLI/library numerical parity and reproducible batch manifests.

## Phase 4: Quality, Documentation and Release Readiness — P3

- [ ] **P3 · Expand independent scientific regression assets.** Files: `tests/`, new reference fixtures, `data/` documentation. Cover poles, leap boundaries, day crossings, signal switches, reset states, storms, mixed cadence and degenerate solvers; document provenance/tolerances. Acceptance: expected results are independent of the implementation under test.
- [ ] **P3 · Add Rust failure-path tests and parser fuzzing.** Files: `src/`, Rust test/fuzz targets, `Cargo.toml`, CI. Exercise truncated/compressed files, conflicting headers, bad epochs and merge errors; assess panic-abort behavior. Acceptance: malformed input cannot silently corrupt data or unexpectedly terminate normal processing.
- [ ] **P3 · Tighten typing and schema contracts.** Files: `gnss_tec/py.typed`, `gnss_tec/_core.pyi`, headers/configuration modules, `pyproject.toml`. Fill annotation gaps; validate units/time/columns at boundaries; use PEP 695 only where useful and preserve Python 3.12 compatibility when considering PEP 696. Acceptance: ty plus installed-wheel consumer checks pass on the supported floor.
- [ ] **P3 · Extract focused modules behind compatible entry points.** Files: `gnss_tec/tec/tec_calculation.py`, `gnss_tec/tec/bias.py`, package exports. Separate bias I/O, signals, QC/arcs, leveling, geometry and product assembly as implementations stabilize. Acceptance: existing API callers remain supported or receive documented deprecations.
- [ ] **P3 · Measure coverage and maintain compatibility matrices.** Files: `.github/workflows/test.yml`, `pyproject.toml`, `tests/`. Retain existing OS/Python/Polars/minimum-dependency jobs and explicit in-memory testing; qualify other engines separately; add coverage and Rust checks; separate core test tools from notebook/plot dependencies. Acceptance: scientific and error branches are tracked, with no invented coverage targets.
- [ ] **P3 · Gate publishing on installed-artifact validation.** Files: `.github/workflows/release.yml`, reusable CI workflow, build configuration. Test built wheels in clean environments; verify version/dependencies/py.typed/stubs, locked builds, import and minimal RINEX-to-TEC; separately exercise free-threaded artifacts. Acceptance: publish depends on successful validation of the artifacts being released.
- [ ] **P3 · Document scientific assumptions and operating limits.** Files: `README.md`, `docs/`, `CHANGELOG.md`. Publish signal/product support, DCB signs, coordinate/time conventions, leveling assumptions, QC meanings, memory budgets and reproducibility commands. Acceptance: examples produce traceable products without relying on hidden defaults.
